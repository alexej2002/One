# Codex: реализация One Premium v1.0 по аудиту

Ты находишься в корне существующего Flutter-проекта **One**. Ознакомься с документами `ONE_PREMIUM_V1_TZ_UPDATED.md` и `ONE_PREMIUM_AUDIT.md`, которые пользователь передаст в репозиторий, и с текущим кодом. Если документов нет по указанным именам, **не выдумывай их содержание**: запроси путь либо используй текст задачи ниже и отметь отсутствие файлов.

## Подтверждённое состояние проекта

Владелец One подтвердил: **приложение ни разу не публиковалось в Google Play, пользователей, реальных покупок и активных подписок нет**. Это первый релиз. Не запрашивай подтверждение отсутствия покупателей повторно; не проводи миграцию покупок и не считай удаление RevenueCat блокирующим действием. Защищай незакоммиченные изменения и несвязанные локальные данные проекта.

## Цель

Заменить платёжный экран One Premium (RevenueCat) на бесплатную локальную активацию **0 € / «Бесплатно»** без платёжного действия, регистрации и сервера. Free/Premium-разделение и существующий дизайн сохраняются. Успешное нажатие «Активировать бесплатно» сохраняет Premium в `shared_preferences` без срока истечения в v1.0.

Текст RU дословно: «One Premium бесплатно. Специальное предложение для первых пользователей. Без списаний и автопродления». Состояния: «Активировать бесплатно», «Premium активен», «Premium активирован» и локализованные ошибки. Никакого обещания пожизненного доступа.

## Стоп-условия и предварительный этап

1. Выведи `git status --short`, не затрагивай незакоммиченные пользовательские изменения и несвязанные файлы.
2. Найди все импорты/вызовы RevenueCat (`Purchases`, `Package`, `Offerings`, `CustomerInfo`, `purchases_flutter`), `FORCE_PREMIUM`, платные тексты и все проверки `isPremium`.
3. Учитывай подтверждение владельца: опубликованных версий, покупателей и обязательств нет. Удали RevenueCat полностью, без механизма миграции или сохранения старых entitlements; сначала найди все зависимости, импорты, конфигурацию и вызовы. Не выполняй проверки внешних кабинетов на наличие исторических продаж.
4. Не создавать аккаунты, сервер, Supabase, Google Play Billing, миграции БД, новые зависимости без необходимости. Не изменять внешний Google Play Console, не публиковать релиз, не делать git commit.

## Реализация первого релиза

### A. Локальное право

- Используй уже имеющиеся `AppState` (`ChangeNotifier`/`provider`) и `shared_preferences`; новый сложный сервис необязателен.
- Читай состояние до `isInitialized` и показа UI. Нет ключа → Free; запись Premium → Premium.
- Асинхронная идемпотентная активация: защита от повторных тапов, сохраняй флаг до смены UI/подтверждения. При ошибке записи показывай локализованную ошибку и оставляй понятный статус, не теряя ранее сохранённое состояние.
- Если хранилище временно не читается, не затирай существующую запись Free-значением; учти перезапуск, офлайн, Android Backup, очистку данных.
- Источник активации `launch_offer`; дата активации справочная, без временного ограничения. Не вводить фальшивые покупки, чеки, токены или «успешную оплату».

### B. UI

- Адаптируй `lib/screens/premium_screen.dart`, сохранив стилистику: преимущества, пометка «Бесплатно», согласованный RU текст, CTA, статус активированного Premium.
- Убери Monthly, Yearly, Lifetime, их цены, `Restore Purchases`, платёжные диалоги и отсылки к автопродлению. Не имитируй платёжную транзакцию.
- Обнови входы в Premium из Settings, архива, темы, виджетов, выбора времени уведомлений и `ContextualPaywallSheet`.
- Исправь жизненный цикл `pendingPremiumAction`: действие срабатывает только после успешного получения права, отмена/выход очищает отложенный callback, старый callback не может примениться при следующей активации.

### C. Premium-функции

- Free: `paper` тема; 7 элементов архива; стандартный режим уведомлений.
- Premium: дополнительные темы `sepia`, `midnight`, `aurora`; остальные элементы существующего архива (текущий алгоритм 365 дней оставить); собственное время уведомлений; функциональность Android-виджета по правилам ниже.
- Сведи проверки доступа к единому источнику, не меняй структуру данных цитат, избранное и пользовательские настройки. Не стирай прежний выбор темы/времени только потому, что приложение временно считает доступ Free.
- Виджет: аудит подтвердил только один нативный widget provider, который можно добавить через launcher. Убери ложное обещание трёх вариантов. Не показывай в неактивированном виджете контент, доступный лишь Premium; передавай актуальный статус нативному виджету и инициируй обновление после активации. Кнопка добавления не должна симулировать действие SnackBar: либо реализуй действительно доступное системное добавление, либо покажи инструкцию добавления через launcher. Сохраняй существующий дизайн без редизайна.

### D. Локализация / юридические материалы

- Добавь новые тексты через `Strings.get` на `en`, `ru`, `de`, `es`, `fr`, `pt_BR`, `pt` (семь вариантов). Убери зашитые английские Premium-сообщения в затронутых экранах.
- Обнови `lib/l10n/legal_content.dart` и `assets/doc/terms-of-use.html`, `assets/doc/privacy-policy.html` с удалением устаревших утверждений о платных подписках, Lifetime, автоматических списаниях и платёжных данных, которых в v1.0 нет. Не выдумывай юридические факты; обозначь URL опубликованных внешних страниц как вопрос, если они не установлены.

### E. Полное удаление RevenueCat

- Удали импорты и вызовы `Purchases`, `Package`, `Offerings`, `CustomerInfo`, `purchasePackage`, `restorePurchases` и остальные элементы RevenueCat, которые больше не используются.
- Удали `purchases_flutter` из `pubspec.yaml`, обнови `pubspec.lock` штатной командой Flutter и удали неиспользуемую нативную конфигурацию SDK, если она есть.
- Удали устаревший обход `FORCE_PREMIUM`, не оставляй фиктивных покупок и платёжных заглушек.
- После изменений выполни поиск по проекту на остатки RevenueCat / `purchases_flutter`; в отчёте укажи результат. Не затрагивай другие настройки и данные приложения.

## Контроль качества

При разрешённой реализации выполни `flutter analyze` и доступные релевантные тесты. Если отсутствуют готовые тесты, добавь минимальные проверки локальной активации, повторного запуска, сбоя сохранения и управления доступом без новых тестовых фреймворков. Не заявляй, что ручное тестирование Android выполнено, если не запускал устройство.

Проверь сценарии: чистая установка Free; активация без сети; быстрые повторные нажатия; перезапуск; повторный вход на Premium; всё четыре преимущества; виджет из launcher до/после Premium; все семь языков; корректные legal тексты; отсутствие SDK и обработчиков покупки после удаления.
